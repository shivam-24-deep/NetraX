## An honest, documented limitation this run surfaced

`04-credential-theft.eml` uses the domain `micr0soft-support.com` (a "0"
substituted for "o" — plain ASCII leetspeak, not a Unicode homoglyph). The
domain-analysis brand-impersonation checks (Phase 4/5) did **not** catch
this specific trick: the Levenshtein-distance check requires the compared
domain to be within 2 edits of `microsoft.com`, and this domain differs by
more (the extra `-support` suffix alone exceeds that), while the
substring-based brand-keyword check requires a literal `"microsoft"`
substring, which `"micr0soft"` (leetspeak) doesn't contain either.

The case still scored MEDIUM (43) — correctly, on the strength of the
credential-request body-language findings and missing authentication
results — but the domain trick itself went undetected by the domain
analyzer specifically. This is a real, current gap (leetspeak character
substitution is a different technique from both true Unicode homoglyphs and
small-edit-distance typos, and isn't covered by either existing check) —
documented honestly here and in `docs/LIMITATIONS.md` rather than papered
over by hand-picking only demo cases the system handles well.
