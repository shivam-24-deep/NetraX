# Limitations

Consolidated from the "known limitation" notes scattered through code
comments and other docs — this is the single place to check "does this
system actually do X reliably."

## Detection gaps (real, current, not hidden)

- **Leetspeak domain substitution** (e.g. `micr0soft.com` with a zero for
  the letter O) is not caught by the homoglyph/typosquat checks — those
  handle true Unicode confusables and small Levenshtein-distance typos, not
  this pattern. See `reports/demo_validation.md` for the case that
  surfaced this.
- **Phone number extraction is heuristic** and will have some false
  positives (reference numbers, dates that look phone-shaped) — documented
  in `indicators.ts` as intentionally permissive.
- **The email content model's "ham" training class is skewed** toward
  2002-2005 tech-mailing-list traffic (SpamAssassin's actual ham corpus),
  not generic modern corporate correspondence — a very formally-phrased
  legitimate business email can score closer to the decision boundary than
  casual phrasing does. Documented in the model's own metadata `notes`
  field (`ml/models/model_metadata.json` → `email_content_classifier`).
- **Domain->IP relationships in the evidence graph are NOT DNS-verified.**
  They represent "this IP appeared in the delivery path for mail claiming
  this From domain" (from the Received chain), not a resolved DNS lookup —
  see the honesty note in `evidence-graph/builder.ts`.

## What requires credentials this environment doesn't have

- **PhishTank** and **MaxMind GeoLite2** both require free registration.
  Adapters are fully built and tested against their documented API
  contracts, but live behavior with real credentials has not been verified
  in this environment — see `.env.example` for how to add them.
- **URLhaus's live query API** (not the bulk CSV download, which works
  without a key) started requiring an `Auth-Key` at some point after this
  project's earlier assumption was documented — corrected in
  `docs/DATA_SOURCES.md` once discovered live.

## What's real but not literally live-deployed

- The Supabase database schema is written and reviewed SQL, never applied
  to a live database (see `docs/FINAL_STATUS.md` §5 for exactly why and
  how to fix it).
- The Edge Functions in `supabase/functions/*/index.ts` are written for
  Deno but have never themselves run under Deno in this session (no Deno
  CLI/Docker available) — `server/local-api.ts` serves the identical
  underlying logic over plain Node HTTP as the working local alternative.

## What's genuinely out of scope for this build

- No LLM is wired in. Explanations are built directly from structured
  Finding data (template-style), never generated by a language model. A
  real LLM could be added later strictly to phrase already-computed
  findings, never to invent evidence or set the score (Rule 8/9) — the
  `LLMAdapter` seam for this is a documented future extension point, not
  implemented.
- No exact attacker identity or physical address is ever claimed (Rule 3/4)
  — geolocation results are always phrased "approximate infrastructure
  geolocation."
- "Not found in threat intelligence" is never phrased as "safe" anywhere in
  the codebase (Rule 5) — verified by explicit unit tests
  (`threat-intel/index.test.ts`).
